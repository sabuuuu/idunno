## key conventions

- all server-only code (db, llm, tmdb clients) lives under `src/lib/` — never imported in client components
- server interactions are exposed via `createServerFn` in `src/server/` — these replace API routes; they run on the server and are safe to call from route loaders or client mutations
- drizzle schema is the single source of truth for types — use `typeof table.$inferSelect` everywhere
- server functions are thin: validate input → call a lib function → return shaped response
- questions are db-driven from day one so they can be swapped without a deploy
- `/result/$sessionId` is a shareable server-rendered page — loader runs on the server, good for social sharing
- client-exposed env vars use the `VITE_` prefix (e.g. `VITE_APP_URL`); server-only vars have no prefix
